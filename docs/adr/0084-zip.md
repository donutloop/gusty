# ADR 0084: `zip` builtin

## Decision

Add a `zip(x, y)` builtin that combines two lists into a list of `[a, b]`
pairs, stopping at the shorter list: `zip([1, 2], [10, 20])` ->
`[[1, 10], [2, 20]]`.

## Details

- **Interpreter**: `evalCall`'s builtins switch adds `case "zip":`. It takes
  two arguments, evaluates each to a list object, and allocates a new list
  appending a nested 2-element list `[x[i], y[i]]` for `i` up to the shorter
  length. Non-list args produce an `*EvalError{"zip expects two lists"}`.
- Example: `zip([1, 2], [10, 20])` evaluates to `[[1, 10], [2, 20]]`.

## Scope

- Interpreter only: the LLVM AOT codegen's builtins folding handles literal
  list/string args for `sum`/`min`/`max`/`reversed`, but constructing nested
  list literals for `zip` is not yet lowered (documented limitation). A future
  ADR will cover codegen `zip` lowering.

## Alternatives Rejected

- **Python-style lazy `zip` iterator** (yields pairs on demand): rejected for
  simplicity — `zip(x, y)` evaluates eagerly to a list of pairs.
