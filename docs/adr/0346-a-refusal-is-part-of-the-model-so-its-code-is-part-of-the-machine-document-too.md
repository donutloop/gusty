# A refusal is part of the model, so its code is part of the machine document too

Status: accepted
Date: 2026-10-16
Related: ADR 0211 (the exit-code half of this row — a refusal is 1, an `llc` rejection 2, a trap 3, on every
path), ADR 0166 (a refusal names the half that is missing, at exit 1), ADR 0249 (a gate and a door that disagree
is how a refusal ships a wrong answer), ADR 0214 (a trap the program cannot name is not handleable — every
built-in trap got a class there; the capability codes are the same argument, one stage earlier), ADR 0302 (one
backend, so a refusal is the only thing that stands between a program and a wrong answer), ADR 0308 (the witness
vocabulary this ADR's tests are written in), ADR 0317 (a guard over a file outside its package needs `-count=1`
to run at all), ADR 0345 (the callable pass whose `--callables` document this registry's shape copies), ADR 0186
(the reference leg, against which every capability refusal is a divergence), roadmap **L11.8** (this row),
roadmap Gap R.165 (the printf refusal), Gap R.232 (a refusal sentence that prints the needle's Go
representation), Gap R.247/R.248 (the ordering builtins' refusals), Gap R.261/R.262 (the container-answer
decline).

## Context

One backend decides what a program means. Where it has no lowering, it says so — and *how* it says so is the
interface. Today that interface is a sentence:

```text
print(list([1, 2]))
  codegen: list(<container>) copies are not supported in the AOT backend yet; CPython answers them —
  build the container with list() and add elements
```

The human path is right: a sentence, in the compiler's own voice, is exactly what a reader wants. The machine
path is the same sentence in a JSON string. To act on it a script has to match on prose that was written for a
person — and prose is not a contract. Edit the wording and the agent's branch does not fail: it stops firing.
The failure mode of a reworded refusal is therefore a script that silently stops covering the shape it used to
notice, which is the worst kind of interface break, because the only symptom is an absence.

This is ADR 0166's rule seen from the other side. ADR 0166 said a refusal must *name the half that is missing*;
ADR 0211 said a refusal must *cost exit 1 whatever path reached it*; both were half of L11.8. What was never
given was the third thing: a name for the refusal itself, stable enough to branch on.

There are 142 `codegen:` refusal sites in `pkg/lang`. Whatever this ADR decides, it has to be true of all of
them eventually — and a mechanism whose coverage decays as sentences are edited is worse than none, because it
will be trusted.

## Decision

**A capability refusal has a code, a suggestion, and owning roadmap rows, and all three live in one registry:
`pkg/lang/capability.go`.**

```go
type CapabilityRefusalKind struct {
	Code       string   // lower.unsupported.<shape> — the stable thing an agent branches on
	Shape      string   // what was refused, in the refusal's own words
	Suggestion string   // what to write instead, or what to wait for
	Rows       []string // the roadmap rows that own the missing half
	Markers    []string // json:"-": the fragments this refusal's sentence contains
	Sample     string   // json:"-": a program that must produce this refusal
}
```

The registry is read three ways, and no reader is allowed its own copy of the list:

1. **`--json`'s `capability` member.** Every `"ok": false` payload the CLI prints (`toolFailurePayload`,
   `reportCompileErr`) carries the entry beside the prose — `{code, shape, suggestion, rows}` — or `null`.
2. **`gustyc --capabilities`**, the whole registry as one self-describing document
   (`{tool, family, backend, kinds}`), in the sense `--variance` and `--callables` are self-describing.
3. **`--schema`**, where `definitions.capabilityRefusal` is the object shape, `definitions.toolFailure` the
   failure payload, and `definitions.capabilityRefusalCode` the **closed enum** — generated by splicing
   `CapabilityRefusalCodes()` into the template at init, not typed by hand.

**A classifier, not a typed error at each refusal site.** `ClassifyCapabilityRefusal(msg)` answers the entry
whose **longest** marker the sentence contains, so `tuple(…)`'s refusal is the tuple row rather than the generic
indirect-call row whose sentence it also contains, and the answer is deterministic rather than registry-order
dependent. A sentence matching nothing answers `false`, and the payload omits the code rather than inventing one.

**Coverage is measured over a corpus, and the tail is an explicit allowlist.**
`integration/capability_coverage_test.go` compiles every conformance program, classifies every error-level
refusal, and fails on one that has no code — unless the sentence is in `capabilityNotACapabilityGap`, where each
entry states why it is the *program's* error rather than a missing lowering (an undefined name, a non-exhaustive
`match`, a text used as a number, an unpacked non-sequence). The registry's unit test reads the claim backwards:
each entry's `Sample` is compiled, and a sample that stops producing its refusal fails the entry.

**The docs table is printed from the registry.** `go run ./tools/captable` emits the markdown inventory
`docs/operations.md` carries; `tools/captable -check` and `TestTheCapabilityDocsTableIsTheRegistry` fail when the
document and the registry disagree. A second guard, `TestTheDocumentedCapabilitySentencesStillExist`, reads every
*message substring* the prose table tells an agent to match and greps it out of this package's own string
literals — placeholders (`<op>`, `%s`, `%q`) are cut and each surviving fragment is asked separately.

Nothing at a refusal site changed. No `fmt.Errorf` in `codegen.go` was touched.

### Alternatives rejected

- **A typed error (`CapabilityError`) at all 142 refusal sites.** A 142-line diff to the code that decides
  programs, in a commit whose job is to name refusals rather than make them — and its failure mode is silent: a
  site whose type was forgotten still compiles, so coverage decays the first time someone adds a refusal in a
  hurry. The registry has the opposite failure mode, which is a red test.
- **An enum in the schema, typed by hand.** Two lists of one fact. A code added to the classifier and not to the
  enum is a payload that fails validation; a code in the enum and not in the classifier is a branch an agent can
  write that never fires. Generating the enum is four lines and removes the class of bug.
- **One code for "unsupported expression".** A code that covers every refusal tells an agent nothing it could not
  get from `phase`, and the moment it is written down it cannot be narrowed without breaking someone. Specific
  shapes, or nothing.
- **Classifying diagnostics by level.** A warning is the checker's opinion about a program that compiles; folding
  warnings into the refusal set would make the coverage claim about the checker's mood. Only errors and hard
  failures are refusals.
- **Giving a code to every sentence, including front-end ones.** A parse error's sentence (`parse error at 1:8:
  expected ")"`) carries no shape to match — the machine field there is `phase`, and the lexer gap behind it is
  Gap R.135/R.245 in the tracker. A family per stage would have meant codes nobody could classify.
- **Making `--capabilities` read the docs.** The docs are a rendering of the registry; the registry is the fact.

## Consequences

**An agent can ask what it cannot write, before it writes it.** `--capabilities` returns the shapes, the codes,
the rewrites, and the rows — one call, no probe-compiles, no prose matching. This is the AGENTS.md
machine-consumption contract applied to the one part of the compiler's output that was pure prose.

**`capability: null` is now meaningful.** Absence used to mean "nobody looked"; the key is always there and says
"this is the program's error, not the backend's". The classifier refusing to guess is what makes that falsifiable
(`TestTheCapabilityClassifierRefusesToGuess`).

**A reworded refusal is a failing test.** Editing a sentence in `codegen.go` without editing its marker stops the
entry's sample from classifying. That is the leash this row existed to put on the prose, and it is the reason the
registry keeps `Markers`/`Sample` as `json:"-"` fields: they are how the registry is *tested*, not a claim about
the language an agent should be reading.

**Exit codes are untouched.** A capability refusal is still exit 1, an `llc` rejection 2, a trap 3 (ADR 0211):
the code says *which shape*, the exit code says *whose fault*. `TestCLIFailureCarriesTheCapabilityCode` pins both
on the same payload.

**Refusals are divergences, and stay that way.** Every entry cites the roadmap rows that own the missing half,
so a refusal is never read as a diagnosis. Where the reference runs the program, the row is the debt; the code
just makes it addressable. Gap R.232 is the counter-example kept in the registry with its own entry — the
membership refusal whose sentence prints the needle's Go representation — because a bad sentence is still a
refusal with a code, and fixing the sentence is the row's job, not the classifier's.

**What this does not buy.** Coverage is over the conformance corpus plus the registry's own samples: a refusal
reachable only from a program nobody has written may still carry no code, and the classifier's silence is then
honest, not complete. The 142 sites are not 142 codes — the registry is 40, which is what the corpus and the
docs table can be held to today; the rest acquire codes as rows around them are touched, each with a measured
sample rather than a typed guess.
